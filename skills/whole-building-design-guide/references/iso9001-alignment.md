# ISO 9001:2015 alignment for a BEP

Use this when a firm or owner wants the BEP to show how it supports an ISO 9001 quality
management system. **Clause numbers and plain-language summaries only.** ISO 9001 is
copyrighted; copies are typically licensed to one user with copying and networking
prohibited. Never quote it, and don't ask the user to paste its text. If exact
requirements matter, point the user to their own licensed copy.

## Why this works

A BEP is a project-level quality plan for digital information: it defines requirements,
who does what, how outputs are checked, how changes are controlled, and what evidence
is kept. Those are the same things ISO 9001 asks an organization to manage, so each BEP
section can be tagged with the clause it helps satisfy.

## Mapping

| BEP section | ISO 9001 clause(s) | What the BEP shows (in plain words) |
|---|---|---|
| 1. Project information | 4.1, 4.2, 8.2.2 | The project's context, its stakeholders, and the requirements that apply (owner, agency, regulatory) |
| 2. Key contacts and roles | 5.3, 7.2 | Who is responsible and has authority, and that they're competent for the role |
| 3. BIM goals | 6.2 | Measurable objectives and how they'll be achieved |
| 4. BIM uses | 8.1, 8.3.2 | Planning of the work, stages, and the controls applied |
| 5. Process design | 4.4, 8.1 | The processes, their sequence, and how they interact |
| 6. Information exchanges | 8.3.3, 8.3.5, 8.4.3 | What each party must deliver (inputs/outputs) and what external providers are told |
| 7. Collaboration procedures | 7.4, 7.5.3, 8.4 | Communication, control of shared files (access, versions, storage), oversight of consultants |
| 8. Technology infrastructure | 7.1.3, 7.1.5 | Software, hardware, and the tools used to check the work |
| 9. CAD and BIM standards | 7.5.2, 8.3.3 | Format and identification rules for documents; standards the team commits to |
| 10. Quality control | 8.3.4, 8.6, 9.1 | Reviews, verification, release criteria, and how results are measured |
| 11. Model structure and deliverables | 8.3.5, 8.5.2 | Defined outputs, acceptance criteria, identification and traceability of files |
| Change control (in 7 or 10) | 6.3, 8.3.6, 8.5.6 | How changes are requested, reviewed, approved, and recorded |
| Nonconforming models / failed checks | 8.7, 10.2 | How failed checks are identified, corrected, and prevented from recurring |
| Lessons learned / BEP updates | 7.1.6, 9.3, 10.3 | Capturing knowledge and improving the BEP for future projects |
| Risks (e.g. CUI, interoperability) | 6.1 | Risks and opportunities identified, with actions |

## How to apply it

- In each BEP section, add a one-line "ISO 9001:" tag listing the clauses.
- Add a short "Evidence kept" note where ISO expects retained records: design inputs,
  review and verification results, change approvals, and corrective actions.
- Keep the wording practical — the aim is to show an auditor where the BEP does the
  work, not to restate the standard.
